## The capacity bond

A node bonds TOKEN in proportion to the bandwidth it declares. The curve is super-linear, so declaring more capacity than you can serve costs more than it is worth:

```text
bond = max(minBond, 12.6 × Mbps^1.2)  TOKEN
```

| Declared capacity | Curve value     |
| ----------------- | --------------- |
| 10 Mbps           | ≈ 200 TOKEN     |
| 100 Mbps          | ≈ 3,165 TOKEN   |
| 250 Mbps          | ≈ 9,500 TOKEN   |
| 1 Gbps            | ≈ 50,000 TOKEN  |
| 10 Gbps           | ≈ 795,000 TOKEN |

`minBond` is a network-wide floor. **On the testnet it is 50,000 TOKEN**, so every declaration up to about 1 Gbps bonds 50,000 TOKEN. `decdn setup --dry-run` and `decdn node bond --mbps <N> --dry-run` print the exact live figure. The team sends testnet TOKEN on request; see [Get testnet funds](/run-a-node/testnet-funds).

To raise your declared capacity later, run `decdn node bond --mbps <N>`. It tops the bond up to the new requirement. The full curve and its rationale are in [ADR 026 § Capacity-bond curve](https://github.com/decdn/decdn/blob/main/adr/026-tokenomics.md#capacity-bond-curve).

## What the bond commits you to

The bond is your registration and capacity commitment. It keeps your node in the active set at its declared tier, and it is what makes you eligible for the operator rebate and for governance weight.

Clients hold you to the rest themselves. A client verifies every chunk against its BLAKE3 hash, pays nothing for a bad range and fetches it from another node, and your node loses local reputation with that peer. Each voucher carries the price your node quoted, so a node is paid exactly its quote.

Your node follows the on-chain content blacklist. Governance can blacklist an operator that keeps serving blacklisted content, which ejects it from the active set: no rebate, no new vote weight, no origin seat. See [Compliance and risk](/run-a-node/compliance).

## Unbonding

`unbond` returns your TOKEN in the same transaction. The bond that stays must still cover your declared tier. To lower your capacity, run `decdn node unbond --to-mbps <N>`. To exit fully, run `decdn node deregister`, then `decdn node unbond --all`.

## How you earn

- **Per byte delivered.** Clients pay per megabyte in USDC through off-chain vouchers. A voucher pays only for bytes the client has verified.
- **Your rate.** You set your own per-MB rate with `payment.rate_per_mb` in USDC base units. The default, `10`, is $0.00001/MB, which is about **$0.01/GB**, the network's target client price. Clients choose the fastest node they can reach, so price within reason and compete on speed. A rate change takes effect after a restart.
- **Settlement.** The node redeems its vouchers on-chain automatically, by default every 5 minutes once a payment lane holds at least 1 USDC. `decdn node lanes` shows what has accrued. There is no claim step: the operator share goes to your address in the same transaction.

## Operator share

Each redemption splits in two steps:

1. **At redemption, on the payment chain.** The payment pool pays you `operatorBps` of the amount in the redemption transaction. The reference deployment sets it to 60%. It is fixed in each pool, so no vote can lower it.
2. **After a sweep, on Ethereum.** The other 40% stays in the pool as your pending protocol share. A permissionless sweep carries it over Circle CCTP to the governance-chain `FeeRouter`, which returns `rebateBps` of it to you while your node is active and sends the rest to the treasury.

At the launch value, `rebateBps` 7500, you receive 60% + 30% = **90%** end to end and the treasury 10%. Governance tunes `rebateBps` within `[0, 9900]`, so the treasury always keeps at least 1% of each sweep.

The treasury leg is also what prices your governance weight: each sweep credits your served bytes up to what its treasury share pays for. See [Governance](/protocol/governance) for the bounds and [ADR 026 § FeeRouter split](https://github.com/decdn/decdn/blob/main/adr/026-tokenomics.md#feerouter-split) for the full design.
